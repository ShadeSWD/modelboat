Модели в КОМПАС-3D

Браузерный конструктор отдаёт корпус как файл для печати, но для учебной работы этого мало: нужны чертежи по ЕСКД, возможность править форму и полноценная сборка. Эта страница — о том, как перенести спроектированную модель в КОМПАС-3D двумя путями: быстрым импортом полигональной геометрии и честным перестроением нативных твердотельных моделей макросом по файлу boat.json.

Этапы работы макроса: из boat.json на смещённых плоскостях строятся эскизы шпангоутов, по ним — операция «По сечениям», затем оболочка с открытой палубой; в сборку вставляются корпус, дейдвуд, перо руля и болванки компонентов на своих местах.

Зачем нативные модели

Конструктор выдаёт геометрию для 3D-печати — этого достаточно, чтобы напечатать корпус, но недостаточно для конструкторской работы:

  • Чертежи по ЕСКД. По нативной детали КОМПАС строит ассоциативные виды, разрезы и сечения, проставляет размеры; по сборке — спецификацию. Курсовой проект оформляется штатными средствами.
  • Правки формы. У детали, построенной операциями, есть дерево построения: можно поменять точки шпангоута, толщину стенки или диаметр отверстия — и модель перестроится. Полигональную сетку из STL так править нельзя.
  • Ассоциативная сборка. Болванки компонентов (платы, моторы, батарея, сервопривод) стоят на местах из проекта: видно, что ничего не пересекается, крышки закрываются, а центровка груза совпадает с расчётной.
  • Контроль по МЦХ. Масса, объём и центр тяжести детали считаются командой МЦХ — и сверяются с водоизмещением и центровкой из методики расчёта (пример — в конце страницы).

Путь А. Импорт STL/STEP из конструктора

Самый быстрый способ увидеть корпус в КОМПАС. Начиная с версии v18 КОМПАС-3D открывает STL как полигональную модель и умеет преобразовывать её в тело:

  1. На странице конструктора экспортируйте корпус в STL (тот же файл, что идёт на печать).
  2. В КОМПАС: Файл → Открыть, тип файлов — «STL», выбрать файл. В диалоге параметров импорта задать миллиметры и «читать как полигональный объект».
  3. Выделить полигональный объект в дереве и выполнить Преобразовать в тело (в разных версиях — команда контекстного меню полигонального объекта либо инструмент панели «Полигональное моделирование»). Если сетка замкнута и без дефектов, получится твердотельный объект.

Если конструктор отдаёт STEP, всё ещё проще: Файл → Открыть → STEP сразу даёт тело с гладкими гранями без всякого преобразования — этот путь предпочтительнее, когда он доступен.

Ограничения импортированной сетки — честно. Тело, полученное из STL, состоит из тысяч плоских треугольных граней: у него нет дерева операций, к нему плохо применяются скругления и оболочка, разрезы на чертежах выходят «рублеными» (ломаная вместо плавного шпангоута), а файл и чертёж по нему тяжёлые. Для картинки и габаритной проверки — годится; для чертежей и правок формы нужен путь Б.

Путь Б. Макрос boat_kompas.py по boat.json

Конструктор экспортирует и boat.json — там сама математика проекта: 21 шпангоут точками, линия борта, линия вала, перо руля и список компонентов с координатами. Макрос boat_kompas.py читает этот файл и строит те же операции, что вы делали бы руками, — только быстро и без ошибок ввода ста с лишним координат.

Что понадобится

  • Windows и КОМПАС-3D v20/v21/v22 — учебная версия подходит (КОМПАС-3D LT не подойдёт: в нём нет API трёхмерных операций);
  • Python 3 с пакетом pywin32 (pip install pywin32) — либо встроенная библиотека макросов «КОМПАС-Макро» из меню «Приложения», где Python уже есть.

Порядок действий

  1. В конструкторе нажмите «Экспорт boat.json» и сохраните файл, например в C:\boat\boat.json.
  2. Скачайте boat_kompas.py (для пробного запуска без конструктора есть готовый пример sample-boat.json — корпус 450 мм, комплект «классика»).
  3. Выполните в командной строке: 
    python boat_kompas.py C:\boat\boat.json
    Макрос сам запустит КОМПАС (или подхватит уже запущенный), построит детали и сборку и сохранит их рядом с boat.json. Ход построения печатается по-русски; каждая деталь строится независимо — одна ошибка не срывает остальные.

Результат — комплект файлов рядом с boat.json: <имя>_корпус.m3d, <имя>_руль.m3d, <имя>_дейдвуд.m3d, болванки компонентов (nano.m3d, motor_130.m3d, ...) и сборка <имя>_сборка.a3d.

Как устроен макрос

Код разбит на независимые функции — по одной на логическую операцию, с комментариями, какими интерфейсами API7 она пользуется:

  • read_boat() — чтение и проверка схемы boat.json;
  • get_kompas() — подключение к КОМПАС по COM (интерфейс IApplication из KompasAPI7);
  • station_sketch() — эскиз шпангоута: смещённая плоскость, сплайн по точкам правой полуветви, зеркальная левая, замыкание по палубе;
  • loft_hull() — операция «По сечениям» по всем эскизам;
  • shell_hull() — оболочка толщиной wall с удалением грани палубы;
  • cut_shaft_hole() — отверстие под дейдвуд: вырез по сечениям между двумя окружностями на концах линии вала;
  • build_rudder(), build_deadwood(), build_component() — перо руля, дейдвудная труба и болванки (параллелепипед или цилиндр по полю shape);
  • build_assembly() — сборка: вставка деталей с матрицами размещения (перенос в координаты компонента, для дейдвуда — ещё и поворот по наклону вала).

Ключевой фрагмент — эскиз шпангоута на смещённой плоскости (сокращённо):

plane = container.PlaneOffsets.Add()          # плоскость || YOZ
plane.Plane = part.DefaultObject(O3D_PLANE_YOZ)
plane.Offset = станция.x                      # смещение вдоль оси корпуса
...
add_spline(draw, points)                      # правая полуветвь: киль -> палуба
add_spline(draw, [(-y, z) for (y, z) in points])   # зеркало в ДП
add_segment(draw, -y_палубы, D, y_палубы, D)  # замыкание по палубе

и лофт с оболочкой:

loft = container.LoftedBosses.Add()           # операция «По сечениям»
for sketch in эскизы_шпангоутов:
    loft.Sections.Add(sketch)
loft.Update()

shell = container.ShellOperations.Add()       # оболочка
shell.Thickness = wall
shell.Faces.Add(грань_палубы)                 # открытая палуба
shell.Update()
Честное предупреждение. Макрос написан по документации API7 (справочник ksAPI7.chm из SDK КОМПАС) и не прогонялся на живом КОМПАС — имена отдельных интерфейсов между версиями SDK менялись, возможны мелкие правки. Самое чувствительное место — поиск грани палубы для оболочки; если оно откажет, макрос честно скажет об этом, а оболочку легко доделать вручную: операция «Оболочка», толщина wall, удалить верхнюю грань. Подробности — в README каталога kompas/.

Чертежи по моделям

Дальше — штатные средства КОМПАС:

  • Виды. Новый чертёж → Вставка → Вид с модели → Стандартные виды, указать <имя>_корпус.m3d: главный вид (бок), сверху (полуширота) и слева (корпус) — это и есть три проекции теоретического чертежа. Виды ассоциативны: перестроили модель — обновился чертёж.
  • Разрезы по шпангоутам. На виде сверху провести линию сечения A–A поперёк корпуса в плоскости нужного шпангоута и выполнить Разрез/сечение — получится истинный контур шпангоута с толщиной стенки. Несколько сечений по длине дают проекцию «корпус» с сеткой шпангоутов.
  • Спецификация сборки. Открыть <имя>_сборка.a3d → Управление → Спецификация → Создать спецификацию по сборке: все детали и болванки компонентов попадут в раздел «Детали»/«Прочие изделия»; наименования уже заполнены макросом из поля name.

Проверка модели

Главная численная сверка: объём подводной части корпуса в КОМПАС должен совпасть с водоизмещением, которое показывает конструктор. По закону Архимеда масса модели равна массе вытесненной воды:

$$\Delta = \rho\,V,$$

где \(V\) — объём корпуса до ватерлинии, а \(\rho\) — плотность воды: 1,00 кг/дм³ для пресной, 1,025 кг/дм³ для морской.

  1. Откройте копию детали корпуса до операции «Оболочка» (в дереве построения перетащите указатель окончания построения выше оболочки — останется сплошное тело лофта) и отсеките всё выше ватерлинии: смещённая плоскость на высоте \(z = T\) и команда Сечение поверхностью с удалением верхней части.
  2. Команда МЦХ модели (панель «Измерения 3D»): в отчёте — объём \(V\), центр тяжести объёма (это центр величины \(x_c\), \(z_c\)) и, при заданном материале, масса.
  3. Сверьте с конструктором по шагам «формула → подстановка → результат». Пример для корпуса 450 мм с осадкой \(T = 35\) мм:
    \(V\) (МЦХ КОМПАС) \(= 920\,197\) мм³ \(= 0{,}92\) дм³
    \(\Delta = \rho\,V = 1{,}00 \cdot 0{,}92 = 0{,}92\) кг (пресная вода)
    конструктор: \(\Delta = 0{,}92\) кг — совпало, модель перенесена верно

Расхождение до 2–3 % — норма: конструктор интегрирует обводы по дискретным точкам шпангоутов, а КОМПАС считает точный объём тела, натянутого сплайнами на те же точки. Расхождение больше 5 % — повод искать ошибку: чаще всего это неверные единицы при импорте (метры вместо миллиметров) или сечение не по той ватерлинии.

Вторая полезная сверка — масса напечатанного корпуса: назначьте детали (уже с оболочкой) материал с плотностью пластика — для PETG около 1,27 г/см³ — и сравните массу из МЦХ с фактическим весом печати с поправкой на заполнение. А сумма масс корпуса и компонентов из перечня не должна превышать \(\Delta\) — иначе модель сядет глубже расчётной ватерлинии; про развесовку и балласт — на странице печати и сборки.
